# 🎓 ITMO.Sync

**ITMO.Sync** — это легковесное *serverless* приложение для автоматического экспорта твоего личного расписания ИТМО в формат **iCalendar (.ics)**. 

Оно позволяет подписаться на расписание с любого удобного устройства *(Apple Calendar, Google Calendar, Outlook и др.)* и поддерживает его в актуальном состоянии абсолютно **бесплатно** за счет использования GitHub Actions и GitHub Pages.

---

## 🌟 Фишки:
* **Полная автоматизация (Serverless):** Запускается по расписанию в GitHub Actions, парсит расписание и публикует ссылки на GitHub Pages. Никакого собственного сервера или хостинга не нужно!
* **Категоризация пар:** Расписание автоматически разбивается на удобные под-календари: *Лекции*, *Практики/Лабораторные*, *Экзамены*, *Спорт*, *Бронирования* и т.д. Можно подписаться только на нужные или сразу на все!
* **Гибкая настройка:** Полный контроль над тем, как выглядят события в календаре через шаблонизацию.
* **Безопасность и Приватность:** Твои пароли от ИСУ надежно хранятся в зашифрованных Secrets. А ссылки на готовые календари защищены секретным префиксом (хэшем), который задаешь ты сам, так что их невозможно подобрать. Благодаря этому репозиторий можно безопасно делать публичным, чтобы использовать GitHub Actions абсолютно бесплатно!

## 🚀 Быстрый старт (Установка)

### Шаг 1: Создай свой репозиторий
1. Нажми зеленую кнопку **«Use this template»** (Использовать этот шаблон) -> **Create a new repository** в верхней части этой страницы.
2. ⚠️ **ВАЖНО:** Оставь тип репозитория **Public (Публичный)**. GitHub предоставляет безлимитные минуты Actions только для публичных репозиториев (для приватных они сильно ограничены или недоступны вовсе). Не переживай за безопасность: твои пароли будут спрятаны в GitHub Secrets, а ссылки на твои календари будут защищены секретным префиксом, который задаешь ты сам. Узнать твое расписание посторонние не смогут!

### Шаг 2: Настрой секреты (Secrets)
Приложению нужно знать, как войти в личный кабинет, а также какой секретный URL использовать для календарей.
В твоем новом репозитории перейди в **Settings** -> **Secrets and variables** -> **Actions**. 
Добавь 3 новых секрета (New repository secret):

* `ITMO_SYNC_USERNAME` — твой табельный номер (например, `123456`).
* `ITMO_SYNC_PASSWORD` — твой пароль от ИСУ.
* `ITMO_SYNC_URL_HASH` — случайная секретная строка. Она будет добавлена к имени файлов, чтобы их нельзя было подобрать. Например, сгенерируй случайный UUID или строку (допустим `my-secret-hash-123`).

### Шаг 3: Настрой права для GitHub Actions
Чтобы скрипт мог публиковать сайт с календарями, нужно выдать ему права:
1. Перейди в **Settings** -> **Actions** -> **General**.
2. В разделе **Workflow permissions** выбери **Read and write permissions** и нажми Save.

### Шаг 4: Включи GitHub Pages
1. Перейди в **Settings** -> **Pages**.
2. В разделе **Build and deployment** -> **Source** выбери **GitHub Actions**.

### Шаг 5: Запусти сборку
1. Перейди на вкладку **Actions**.
2. Слева выбери воркфлоу **Sync & Deploy ITMO Schedule**.
3. Нажми **Run workflow** -> **Run workflow**.
4. После успешного завершения сборки, на вкладке **Pages** (или прямо на главной репозитория в разделе Environments) появится базовая ссылка на твой сайт (формата `https://<твой-юзернейм>.github.io/<имя-репозитория>/`).
5. **Важно:** чтобы открыть само расписание, тебе нужно вручную добавить твой секретный хэш в конец этой ссылки. Итоговый URL должен выглядеть так: `https://<твой-юзернейм>.github.io/<имя-репозитория>/<твой-секретный-хэш>/`. Перейди по ней — там будет твой личный сайт с ссылками на подписку!

## ⚙️ Конфигурация (`settings.yaml` / Variables)

Ты можешь гибко настроить внешний вид событий, переименовать типы пар или изменить эмодзи. Сделать это можно **двумя способами**:
1. Отредактировать файл `settings.yaml` прямо в корне репозитория.
2. Добавить конфигурацию через **Variables** в GitHub: **Settings -> Secrets and variables -> Actions -> Variables**. Имя переменной должно начинаться с префикса `ITMO_SYNC_` (например, `ITMO_SYNC_DEFAULT_CALENDAR_PREFIX`). Этот способ удобен, если ты не хочешь делать коммиты при каждом изменении конфига.

### 1. Шаблоны событий
Управляют тем, как пары будут называться и выглядеть внутри твоего календаря.

**Доступные переменные:**
- `{title}` — название дисциплины
- `{type}` — тип занятия (например, "Лекция")
- `{label}` — эмодзи для типа занятия
- `{teacher}` — ФИО преподавателя
- `{format}` — формат проведения ("Очно", "Дистанционно")
- `{location}` — аудитория / место проведения
- `{url}` — ссылка на пару (например, Zoom/Teams)
- `{note}` — дополнительные примечания

**Основные шаблоны:**
- `summary_template`: Шаблон названия обычных пар.
- `description_template`: Шаблон подробного описания обычных пар.
- `booking_summary_template` / `booking_description_template`: Отдельные шаблоны специально для бронирований коворкингов и аудиторий.

### 2. Переименование типов и эмодзи (Метки)
Если тебе не нравится, как называются типы занятий или ты хочешь поменять иконки, это можно сделать здесь же:

- `type_names`: Позволяет задать свои названия для каждого системного типа занятия. Ключом выступает оригинальное название из ИСУ (например, переименовать `"Лекции"` в `"Лекция"`).
- `labels`: Позволяет задать уникальные эмодзи-метки для каждого типа (например, поставить `"🔥"` для `"Экзамен"`).

Пример куска `settings.yaml`:
```yaml
summary_template: "{label} {title} — {type}. {format}"
booking_summary_template: "🗓️ Бронь: {title}"

labels:
  "Лекции": "📚"
  "Экзамен": "🔥"
```

### 3. Системные поля (URL и Аудитория)
По умолчанию скрипт автоматически заполняет стандартные поля `LOCATION` (аудитория) и `URL` (ссылка на пару, например Zoom) внутри формата iCalendar, чтобы они корректно подхватывались интерфейсом твоего календаря. 
Если тебе это мешает, и ты хочешь оставить эту информацию исключительно в тексте описания (через переменные `{url}` и `{location}` в шаблоне), ты можешь отключить их системное заполнение:
```yaml
include_location: false
include_url_field: false
```

### 4. Настройка частоты обновлений
По умолчанию расписание синхронизируется 4 раза в день. Если ты хочешь изменить это время, просто отредактируй файл `.github/workflows/deploy.yml` в своем репозитории.
Найди блок `schedule:` и измени значение `cron`:
```yaml
  schedule:
    - cron: '17 3,9,15,20 * * *'  # Запускать в 03:17, 09:17, 15:17 и 20:17 UTC
```
*Подробнее про синтаксис cron можно почитать на сайте [crontab.guru](https://crontab.guru).*

## ❓ Частые вопросы (FAQ)

### Как подписаться на календарь?
Не скачивай `.ics` файл напрямую (иначе расписание не будет автоматически обновляться). Скопируй ссылку (нажав на кнопку "Скопировать ссылку") и вставь её в настройки своего приложения-календаря по URL (Подписка по URL / Подписка из сети).

### Обязательно ли подписываться на все календари сразу?
Нет! Скрипт генерирует как общий файл `general` (всё расписание вместе), так и отдельные файлы для каждого типа (лекции, практики, бронирования). Ты можешь подписаться только на то, что тебе действительно нужно.

### Как часто обновляется расписание?
Запуск скрипта обновления настроен через cron в файле `.github/workflows/deploy.yml` (по умолчанию 4 раза в сутки в 03:17, 09:17, 15:17 и 20:17 UTC). 
**Обрати внимание:** так как сервис работает на бесплатных запланированных задачах (Scheduled Events) GitHub Actions, фактический запуск может откладываться на несколько минут или даже часов в периоды высокой нагрузки на сервера GitHub.

### Почему расписание обновилось на сервере, но не обновилось у меня в телефоне?
Время обновления расписания в твоем устройстве зависит от самого приложения календаря. 
Например, Google Календарь сильно кэширует данные по ссылкам и может запрашивать обновления лишь раз в несколько часов, а иногда и вплоть до суток. К сожалению, на это никак нельзя повлиять со стороны сервера. Apple Calendar обновляется гораздо быстрее.

### Мне не нравится формат названия пар или иконки. Как мне изменить это?
Ты можешь легко настроить внешний вид и формат абсолютно любых событий! Смотри раздел **Конфигурация** выше.

## 🛠 Технический стек
- **Python 3.12+**
- Пакетный менеджер [uv](https://github.com/astral-sh/uv)
- Парсинг: `httpx` + внутренний API ИТМО (пакет `itmo_schedule`)
- Генерация: `icalendar`, `Jinja2`
- CI/CD: GitHub Actions + GitHub Pages
