# 🗓️ ITMO.Sync

**ITMO.Sync** — это легковесное *serverless* приложение для автоматического экспорта твоего личного расписания ИТМО в формат **iCalendar *(.ics)***. 

Оно обладает гибкой системой конфигурации *(позволяет переименовывать дисциплины, настраивать шаблоны отображения пар и фильтровать лишнее)*. Приложение позволяет подписаться на расписание с любого устройства *(Apple Calendar, Google Calendar, Outlook и др.)* и поддерживает его в актуальном состоянии абсолютно **бесплатно** за счет использования GitHub Actions и GitHub Pages.

> [!NOTE]
> Это **Serverless** решение *(работает через GitHub Actions без хостинга)*. 
> Если ищешь серверное решение, то советую [itmom](https://github.com/madfanat/itmom) *(оттуда взята библиотека для API ИТМО)*.


## 📌 Особенности:
* **Полная автоматизация:** Запускается по расписанию в GitHub Actions, парсит расписание и публикует ссылки на GitHub Pages. Никакого сервера, хостинга и скачиваний не нужно!
* **Категоризация пар:** Расписание автоматически разбивается на удобные под-календари: *Лекции*, *Практики/Лабораторные*, *Экзамены*, *Спорт*, *Бронирования* и т.д. Можно подписаться только на нужные или сразу на все.
* **Гибкая настройка:** Полный контроль над тем, как выглядят события в календаре через шаблонизацию. Можно переименовывать или исключать пары из календаря при помощи гибкой фильтрации.
* **Безопасность и Приватность:** Твои пароли надежно хранятся в приватных Secrets. Ссылки на готовые календари защищены секретным префиксом, который задаешь ты сам. *Кроме того, скрипт удаляет артефакты сборки, чтобы никто не смог увидеть твой хэш в архиве Actions.* Благодаря этому репозиторий можно безопасно делать публичным, чтобы использовать GitHub Actions абсолютно бесплатно.
* ⚠️ **Задержка обновлений:** Из-за особенностей бесплатного планировщика GitHub Actions, расписание может обновляться с задержкой. Если для тебя важно получать изменения, то советую серверное решение [itmom](https://github.com/madfanat/itmom).


## 🚀 Быстрый старт:

### Шаг 1: Создай свой репозиторий
1. Нажми зеленую кнопку **«Use this template»** → **Create a new repository** в верхней части этой страницы.
2. ⚠️ **ВАЖНО:** Оставь тип репозитория **Public**. GitHub предоставляет безлимитный Actions только для публичных репозиториев. Всё безопасно: твои пароли спрятаны в Secrets, а ссылки на календари будут защищены секретным префиксом, который задаешь ты сам.

### Шаг 2: Настрой секреты *(Secrets)*
Приложению нужно знать, как войти в личный кабинет, а также какой секретный URL использовать для календарей. 
В твоем новом репозитории перейди в **Settings** → **Secrets and variables** → **Actions**. 
Добавь 3 новых секрета *(New repository secret)*:

* `ITMO_SYNC_USERNAME` — твой табельный номер *(например, `123456`)* или другой известный тебе логин.
* `ITMO_SYNC_PASSWORD` — твой пароль от личного кабинета.
* `ITMO_SYNC_URL_HASH` — случайная секретная строка. Она будет добавлена к ссылке, чтобы ограничить внешний доступ. Например, сгенерируй случайный UUID, хэш или сложную строку с допустимыми символами.
  * ⚠️ **ВАЖНО:** обязательно запомни указанную строку, она понадобится при доступе к расписанию.

### Шаг 3: Включи GitHub Pages
1. Перейди в **Settings** → **Pages**.
2. В разделе **Build and deployment** → **Source** выбери **GitHub Actions**.

### Шаг 4: Запусти сборку
1. Перейди на вкладку **Actions**.
2. Слева выбери воркфлоу **Sync & Deploy ITMO Schedule**.
3. Нажми **Run workflow** → **Run workflow**.
4. После завершения сборки, на вкладке **Pages** появится базовая ссылка на твой сайт.
5. ⚠️ **ВАЖНО:** чтобы открыть само расписание, тебе нужно вручную добавить твой секретный хэш в конец этой ссылки. Итоговый URL должен выглядеть так: `https://<твой-юзернейм>.github.io/<имя-репозитория>/<твой-секретный-хэш>/`. Перейди по ней — там твой личный сайт с ссылками на подписку!

*Дальнейшие обновления и деплой расписания будут происходить автоматически — по заданному расписанию или при любом пуше в твой репозиторий.*


## ⚙️ Конфигурация:

Ты можешь настроить внешний вид событий, переименовать или исключать пары и многое другое. Сделать это можно **двумя способами**:
1. Отредактировать файл `settings.yaml` в корне твоего репозитория.
2. Добавить конфигурацию через **Variables** в твоём репозитории: **Settings → Secrets and variables → Actions → Variables**. Имя переменной должно начинаться с префикса `ITMO_SYNC_` *(например, `ITMO_SYNC_DEFAULT_CALENDAR_PREFIX`)*.

### 1. Шаблоны событий
Управляют тем, как пары будут называться и выглядеть внутри твоего календаря.

**Доступные переменные:**
- `{title}` — название дисциплины
- `{type}` — тип занятия *(например, "Практические занятия")*
- `{label}` — метка для типа занятия
- `{format}` — формат проведения *("Очно", "Дистанционно" или "Смешанный формат")*
- `{teacher}` — ФИО преподавателя полностью *(если есть)*
- `{teacher_short}` — ФИО преподавателя кратко, формат: *Фамилия И. О.* *(если есть)*
- `{location}` — аудитория / место проведения *(если есть)*
- `{url}` — ссылка на пару *(если есть)*
- `{note}` — дополнительные примечания *(если есть)*

**Основные шаблоны:**
- `summary_template`: Шаблон названия обычных пар.
- `description_template`: Шаблон подробного описания обычных пар.
- `booking_summary_template` / `booking_description_template`: Отдельные шаблоны для бронирований.

### 2. Исключение и переименование предметов
Если ты хочешь убрать какие-то предметы из календаря или переименовать их, используй блоки `ignore` и `renames`:

```yaml
ignore:
  - "История России"              # Исключить весь предмет целиком
  
  - match: "Физическая культура"  # Исключить только очные занятия
    format: IN_PERSON
    
  - match: "БЖД"                  # Исключить только онлайн-лекции
    type: LECTURE
    format: REMOTE

renames:
  - "Иностранный язык": "Английский"             # Переименовать предмет везде
  
  - match: "Архитектура вычислительных систем"
    type: LAB                                    # Переименовать только лабораторные
    format: IN_PERSON                            # и только если они очные
    to: "АВС (Лабы)"
```

### 3. Переименование типов и меток
Если тебе не нравится, как называются типы занятий или ты хочешь поменять метки, это можно сделать здесь же:

- `type_names`: Позволяет задать названия для каждого типа занятия. Ключом выступает системное имя типа *(например, переименовать `PRACTICAL` в `"Практика"`)*.
- `labels`: Позволяет задать уникальные метки *(`label`)* для каждого типа *(например, поставить `"🔥"` для `EXAM`)*.

Пример настройки `settings.yaml`:
```yaml
type_names:
  PRACTICAL: "Практика"
  LAB: "Лабораторная"

labels:
  LECTURE: "📚"
  EXAM: "🔥"
```

### 4. Системные поля
По умолчанию скрипт автоматически заполняет поля `LOCATION` *(аудитория и адрес)* и `URL` *(ссылка на пару, например Zoom)* внутри формата iCalendar, чтобы они корректно отображались интерфейсом календаря. 
Если тебе это мешает, ты можешь отключить их системное заполнение:
```yaml
include_location: false
include_url_field: false
```

### 5. Глобальные настройки календаря
Ты можешь изменить период, за который выгружается расписание, и дефолтное название для календаря.
Период задается в формате `ММ-ДД` *(месяц и день)*. Год вычисляется автоматически.

```yaml
fetch_start: "09-01"                      # С какого числа выгружать расписание
fetch_end: "06-30"                        # По какое число выгружать расписание (с переносом на следующий год)
default_calendar_prefix: "ИТМО"           # Префикс названия календаря (напр. "ИТМО: Лекции")
```

### 6. Настройка частоты обновлений
По умолчанию расписание синхронизируется 4 раза в день. Если ты хочешь изменить это время, просто отредактируй файл `.github/workflows/deploy.yml` в своем репозитории.
Найди блок `schedule:` и измени значение `cron`:
```yaml
  schedule:
    - cron: '17 3,9,15,20 * * *'  # Запускать в 03:17, 09:17, 15:17 и 20:17 UTC (соответствует 06:17, 12:17, 18:17 и 23:17 по МСК)
```
*Подробнее про синтаксис cron можно почитать на сайте [crontab.guru](https://crontab.guru).*
